# Assignment report and demonstration checklist

Use this as a working checklist for the required PDF report and 10–15 minute demonstration. Replace every placeholder with facts and evidence from the actual approved application. Do not invent interviews, screenshots, test results or team contributions.

## PDF report structure

1. **Cover page** — application name, course, assignment, group number, member names and GitHub usernames.
2. **Problem and users** — problem statement, target users, research method, interview summary and key findings.
3. **Design** — link to the approved Figma prototype, design system, annotated screens and navigation flow.
4. **Requirements** — functional and non-functional requirements with acceptance criteria.
5. **Architecture** — Clean Architecture layers, BLoC/Cubit responsibilities and a system architecture diagram.
6. **Data design** — final ERD, collection/table definitions, relationships, indexes and data lifecycle.
7. **Firebase implementation** — authentication providers, CRUD operations, security rules and deployment evidence.
8. **Preferences** — at least three persisted settings and how they affect the app.
9. **Testing and quality** — unit/widget/integration test cases, analyzer output, coverage report and build evidence.
10. **Collaboration** — branch/commit/PR evidence and a clear, genuine account of each member's work.
11. **Limitations and reflection** — known issues, trade-offs and what the team would improve.
12. **Appendices** — relevant screenshots, test output, diagrams and source links.

## Suggested 12-minute demo

| Time | Demonstration |
|---|---|
| 0:00–1:00 | Introduce the problem, target user and app purpose |
| 1:00–2:30 | Walk through the Figma design and navigation |
| 2:30–4:00 | Register, verify email and sign in; show Google sign-in if configured |
| 4:00–6:30 | Demonstrate create, read, update and delete on real Firestore data |
| 6:30–7:30 | Show persisted preferences after restarting the app |
| 7:30–9:00 | Explain Clean Architecture, Cubit flow and ERD |
| 9:00–10:00 | Show Firestore security rules and owner isolation |
| 10:00–11:00 | Show tests, analyzer and successful Android build evidence |
| 11:00–12:00 | Explain collaboration, limitations and conclusion |

Keep the complete recording within the assignment's 10–15 minute requirement.
